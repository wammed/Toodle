---

本書は、**Toodle** におけるデータ保護方針、オフライン耐性、キャッシュ整合性モデル、ファイル I/O 安全性、および Wayland プロトコルにおける入力領域分離アーキテクチャを解説するドキュメントです。

---

## 1. ゼロテレメトリ & プライバシー保護方針

Toodle は、ユーザーのプライバシーとデータ主権を最優先に設計されています。

- **ゼロトラッキング / ゼロテレメトリ**:
  - 利用状況の追跡、クラッシュログの外部送信、アナリティクス、および広告関連の通信は 100% 存在しません。
- **機密情報の完全隔離**:
  - ウィジェットはローカルファイルシステム上の `~/.config/toodle/`（設定およびキャッシュ）のみにアクセスし、システム内の個人ファイル、キーストローク、または他プロセスのメモリ情報を読み取ることはありません。
- **一般ユーザー権限での完全動作**:
  - root 権限や `sudo`、追加の Capabilities、setuid 権限を一切要求しません。

---

## 2. 天気サブシステムの通信 & キャッシュ整合性

Toodle は天候情報の取得に [Open-Meteo API](https://open-meteo.com/) を利用します。ネットワーク通信の安全性とデータ整合性を担保するため、以下の多層防御機構を実装しています。

### ① 2段階ローカル永続キャッシュ
- **現在天気**: 30 分間のローカルキャッシュ
- **週間天気**: 3 時間のローカルキャッシュ
- **オフライン完全フォールバック**:
  - ネットワーク切断時や API サーバー障害時でも、直近に保存されたキャッシュデータを活用して表示を継続します。
  - キャッシュが存在しない場合でも、UI のクラッシュやハングアップを回避し、「--」等の安全なプレースホルダーにフォールバックします。

### ② リクエスト世代カウンター (Stale Response Protection)
非同期通信においてネットワーク遅延や再試行が発生した場合、古いリクエストの応答が新しいリクエストの後に到着する「レースコンディション」が発生するリスクがあります。
Toodle では、天気リクエストごとにインクリメントされる **世代 ID（Generation Counter）** を付与し、最新の世代 ID と一致しない遅延レスポンスを破棄することで、古い天候データによる上書きを 100% 防止しています。

### ③ クロックスキュー保護 & スキーマ検証
- **クロックスキュー保護**: システム時刻の急激な巻き戻しや NTP 同期によるズレが発生した場合でも、キャッシュ有効期限の不整合によって永久に更新が停止することがないよう、未来時刻および過去時刻の妥当性を検証します。
- **厳格な JSON バリデーション**: API から返却されたレスポンスに対し、最低 7 日分の予報配列の充足確認、気温・降水確率の値域チェック、不正な NaN/Null の排除を行ってからメモリおよびディスクに反映します。

## 3. ファイル I/O 安全性 & アトミック永続化

設定ファイル（`config.toml`）および天気キャッシュファイル（`cache.json`）の保存処理には、停電やプロセス強制終了時でもデータが破損しない **アトミック保存パターン** を採用しています。

```text
[保存データ]
     │
     ▼
一時ファイルへの書き込み (`.{filename}.tmp.{pid}`)
     │
     ▼
ディスク強制同期 (`sync_all()`)
     │
     ▼
アトミック置換 (`fs::rename`) ───> 目的のファイルへ瞬時に置換 (破損ゼロ)
```

1. **プロセス ID（PID）付き一時ファイル**:
   - `.{filename}.tmp.{pid}` 形式の一時ファイルに全データを一括書き込みします。複数インスタンスの競合による書き込み衝突を防ぎます。
2. **`sync_all()` による物理フラッシュ**:
   - OS のカーネルバッファから物理ディスクへのフラッシュを確実に完了させます。
3. **アトミック `rename`**:
   - POSIX のアトミックなリネーム操作により、ファイルが「書きかけの不完全な状態」で読み出されるリスクを完全に排除します。

## 4. Wayland Layer Shell セキュリティ & Input Region 透過

Toodle は Wayland の公式プロトコル拡張である `wlr-layer-shell` を介して動作します。

- **Input Region（入力領域）の局所化**:
  - ウィジェット本体はデスクトップ全体を透明なウィンドウで占有しません。時計・天気の描画矩形（`content_bounds`）のみを入力受付領域としてコンポジタに申告します。
  - これにより、意図しないクリックスルー阻害や、デスクトップ背面に対する「不可視のクリックジャック」が発生する余地を根本から排除しています。
- **サーフェス層の分離**:
  - ウィジェット本体は壁紙直上の `Layer::Bottom` に配置され、他の通常アプリケーションウィンドウ（`Layer::Top` / XDG Toplevel）の最前面を遮ることはありません。
  - 操作時のみポップアップや Edit パネルが `Layer::Top` に一時展開され、操作完了と同時に速やかに破棄されます。
